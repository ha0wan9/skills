Protocol-change rule

Any edit to protected files, the metric parser, the baseline source, the eval split, or the seed policy after a run launches invalidates that run. Record the change, reason, approver, and effective run ID in protocol-changes.md before the deviating run.

2.2 Prior runs and probes

Measured evidence from past runs that informs this study. Each chart should declare the recipe / eval split / date in its title; numbers without that header are not citable in Design.

Where each evidence chart should come from
  • Prior probe sweeps — short / canonical-recipe measurements; replace the example data block in the <script> section.
  • Per-component breakdowns — stacked bars by op-group or by sub-module; one row per variant.
  • Ledger-derived plots — read directly from runs.jsonl via a small loader (preferred over hand-curated data once a study has > 5 runs).
Refresh rule: every chart's title must name the recipe and the data source path; if a number is shown without provenance, an audit flags it.

How many tracks?
