# Public Design-System Case Model

Use public design systems as structural examples only. Do not copy their visual assets, token values, proprietary artwork, or brand-specific motifs.

## Reference Cases

- IBM Carbon: open-source product design system with design tools, code libraries, guidelines, and contribution paths.
- GOV.UK Design System: styles, components, patterns, accessibility, and service guidance.
- Atlassian Design System: tokens, foundations, components, content guidance, and tooling.
- Microsoft Fluent 2: multi-platform component system and design resources.
- Shopify Polaris: admin and commerce-oriented foundations, tokens, components, icons, and patterns.

## Reusable Taxonomy

Use this taxonomy for `asset-pack.yaml` modules:

- `foundation`: color swatches, type specimens, spacing scales, grid references, elevation samples, motion frames.
- `icon`: original icon family, state icons, feature icons, action icons.
- `diagram`: flow blocks, connectors, annotations, system maps, data relationship primitives.
- `component`: UI component mockups, component states, empty/error/loading states, composite UI panels.
- `pattern`: task-flow scenes, onboarding, dashboards, forms, navigation, review surfaces, presentation frames.
- `illustration`: original spot illustrations, hero scenes, editorial graphics, conceptual metaphors.
- `background`: reusable surfaces, subtle textures, framing devices, product-neutral scene backdrops.

## Governance Checks

Every module should define:

- intended user and use case
- asset type and reuse boundary
- source sketches
- accessibility and legibility requirements
- output sizes and formats
- license notes
- review owner and acceptance criteria
